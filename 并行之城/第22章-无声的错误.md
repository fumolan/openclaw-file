# 第22章：无声的错误

## 一

阚工在东五车间的异步任务链中发现了问题——任务B执行失败——但异步链静默终止——没有异常处理——没有后续任务执行——整个流程卡住。

"CompletableFuture的异常被吞掉了。"阚工说。

东五车间的异步流程——任务A完成后触发任务B——任务B完成后触发任务C。使用CompletableFuture实现——A.thenApply(B).thenApply(C)。任务A成功——任务B抛出异常——任务C没有执行——整个链静默终止。

"CompletableFuture的异常不会自动抛出——需要显式处理。"阚工在面板上解释。"thenApply()内部的异常被捕获——存储在CompletableFuture内部——不会传播到调用者。调用者需要调用exceptionally()或handle()来处理异常。"

阚工调出CompletableFuture的异常处理机制——CompletableFuture内部存储了一个结果或一个异常。thenApply()执行时——如果前一个阶段正常完成——执行lambda——如果lambda抛出异常——捕获异常——存储在当前CompletableFuture中——后续的thenApply()不会执行——整个链终止。

"静默终止的原因——没有调用get()或join()——异常不会抛出。"阚工说。"如果调用future.get()——get()会抛出ExecutionException——包装了原始异常。但东五车间的代码是异步的——没有调用get()——异常被存储但没有抛出。"

## 二

阚工检查了东五车间的CompletableFuture使用方式。

原代码：

CompletableFuture
    .supplyAsync(() -> taskA())
    .thenApply(resultA -> taskB(resultA))
    .thenApply(resultB -> taskC(resultB));

任务B抛出异常——taskC不执行——整个链静默终止——没有任何日志——没有任何告警。

"异常处理缺失。"阚工说。"CompletableFuture的异步链必须有异常处理——否则异常被吞掉——流程静默终止。"

阚工修改代码：

CompletableFuture
    .supplyAsync(() -> taskA())
    .thenApply(resultA -> taskB(resultA))
    .thenApply(resultB -> taskC(resultB))
    .exceptionally(ex -> {
        log.error("异步任务链异常", ex);
        return null;
    });

exceptionally()捕获整个链路上的异常——包括taskA、taskB、taskC中抛出的任何异常。异常被捕获后——记录日志——返回fallback值——整个链不会静默终止。

"exceptionally()是异常处理的兜底。"阚工说。"它捕获所有未处理的异常——提供fallback逻辑——保证流程不会静默失败。"

## 三

阚工进一步分析CompletableFuture的其他异常处理方式。

exceptionally()——捕获异常——提供fallback值。适用于需要返回fallback值的场景。

handle()——同时处理正常结果和异常——参数包含结果和异常——需要判断异常是否为null。适用于需要统一处理正常和异常场景的场景。

whenComplete()——处理完成后执行的操作——不影响结果——参数包含结果和异常——没有返回值。适用于记录日志、资源清理等场景。

"三种异常处理方式——适用于不同场景。"阚工在面板上写。"exceptionally()——仅需处理异常——返回fallback值。handle()——需要统一处理正常和异常——返回新值。whenComplete()——处理完成后执行操作——不修改结果。"

阚工在东五车间改进后的代码中加入了三种异常处理——

exceptionally()——捕获异常——记录日志——返回fallback值。

handle()——统一处理正常和异常——正常结果继续传递——异常记录日志。

whenComplete()——无论成功失败——记录完成状态——用于监控。

## 四

阚工分析了CompletableFuture的异步链编排——串行、并行、组合。

串行——A.thenApply(B).thenApply(C)——A完成后执行B——B完成后执行C。异常处理——任何一个阶段抛出异常——后续阶段不执行——整个链终止。

并行——CompletableFuture.allOf(A, B, C)——A、B、C并行执行——全部完成后继续。异常处理——任何一个阶段抛出异常——allOf()立即完成——其他阶段继续执行但结果被忽略。

组合——A.thenCompose(a -> B(a))——A完成后执行B——B返回CompletableFuture——两阶段异步组合。thenCompose()类似于flatMap——将两个异步操作串联。

"CompletableFuture的编排能力——可以实现复杂的异步流程。"阚工说。"但编排越复杂——异常处理越重要——任何一个阶段的异常都可能影响整个流程。"

阚工在东五车间的异步流程中加入了全链路的异常处理——每个阶段都有exceptionally()——最外层有handle()——保证任何异常都能被捕获和记录。

## 五

阚工完成了东五车间的CompletableFuture异常处理改造——异步流程不再静默终止——异常被捕获——日志被记录——告警被触发。

他在工作日志上写下CompletableFuture的使用规范：

"CompletableFuture的异常不会自动抛出——需要显式处理。调用get()或join()——异常通过ExecutionException抛出。异步链没有调用get()——必须使用exceptionally()或handle()处理异常。"

"异常处理的最佳实践——每个异步链末尾都有exceptionally()或handle()。中间阶段可以加入whenComplete()记录日志。关键阶段可以单独处理异常——提供细粒度的fallback逻辑。"

"CompletableFuture的编排——串行用thenApply()或thenCompose()。并行用allOf()或anyOf()。组合多个阶段——thenCombine()——处理两个阶段的结果。"

"异常处理不只是记录日志——需要考虑业务逻辑——任务失败后是否重试——是否触发告警——是否需要人工干预——这些都应该在异常处理中考虑。"

阚工走出东五车间——异步链路在异常处理后稳定运行——任务失败后日志记录——告警触发——运维人员介入——不再静默终止。CompletableFuture的名字包含Future——但异步的未来不只是成功——还包括失败。处理失败的能力——才是CompletableFuture完整的能力。
