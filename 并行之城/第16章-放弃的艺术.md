# 第16章：放弃的艺术

## 一

阮钴在东九车间发现了一个现象——多个线程同时检查同一个条件——条件满足时——多个线程同时执行了本应由单个线程执行的操作。

"不该同时执行。"阮钴说。

东九车间的场景——一个定时任务检查设备状态。设备状态异常时——触发告警。问题在于——五个线程同时检查设备状态——设备状态异常——五个线程同时触发告警——同一个设备的异常被告警了五次。

"五个线程——五个告警——同一个设备——同一个异常。"阮钴调出告警日志——同一秒钟——五条相同的告警记录——五个线程各自发送了一条。

代码逻辑——每个线程在执行时——先检查设备状态——if (device.isAbnormal()) { sendAlert(); }——五个线程同时执行——五个if条件同时为true——五个sendAlert()同时执行。

"没有互斥。"阮钴说。"五个线程各自检查条件——各自认为条件满足——各自执行操作。"

## 二

阮钴分析——Balking模式可以解决这个问题。Balking——犹豫——当多个线程同时检查条件——条件满足时——只有一个线程执行操作——其他线程放弃。

"Balking的核心思想——条件满足时——只执行一次——后续线程检测结果——发现已经被执行——放弃。"

阮钴查看了东九车间的代码——没有Balking逻辑——没有guard标记——没有状态检查——纯粹的if条件判断。五个线程——五个独立的if——五个独立的执行。

"需要加guard。"阮钴在面板上设计Balking模式的实现——一个boolean标记——alertSent——初始值false。第一个线程检查条件——设备异常——检查alertSent——false——设置alertSent为true——发送告警。第二个线程检查条件——设备异常——检查alertSent——true——放弃——不发送告警。

阮钴补充——alertSent必须是volatile的——保证多个线程之间的可见性。否则——第一个线程设置alertSent为true——但第二个线程可能读到旧值false——仍然执行告警。

"volatile保证可见性——一个线程写入——其他线程立刻看到。"

## 三

阮钴在东九车间实现了Balking模式——代码改动不大——在告警发送前增加了一个volatile boolean guard。

但实现后——新问题出现。告警发送后——设备异常持续——告警不再发送——这是正确的行为。但设备恢复正常后——再次异常——告警仍然不发送——因为alertSent仍然是true。

"guard需要重置。"阮钴说。"设备恢复正常时——重置alertSent为false——下一次异常时——可以再次告警。"

阮钴在设备状态恢复正常的逻辑中——增加了alertSent = false的重置。

告警逻辑完整了——设备异常——检查alertSent——false——设置alertSent为true——发送告警。设备恢复正常——重置alertSent为false。设备再次异常——检查alertSent——false——设置alertSent为true——发送告警。

"但还有一个问题。"阮钴说。"alertSent的检查和设置不是原子的。两个线程可能同时读到alertSent为false——同时设置为true——同时发送告警。"

阮钴查看代码——if (!alertSent) { alertSent = true; sendAlert(); }——两个操作——读和写——分开执行——中间可能被其他线程插入。

"需要synchronized或原子操作。"阮钴把if判断和设置合并成一个原子操作——synchronized(alertLock) { if (!alertSent) { alertSent = true; sendAlert(); } }。或者使用AtomicBoolean的compareAndSet(false, true)——一个原子操作——检查并设置。

阮钴选择AtomicBoolean——更轻量级。alertSent.compareAndSet(false, true)——如果当前值是false——设置为true——返回true。如果当前值是true——不设置——返回false。返回true的第一个线程执行告警——返回false的其他线程放弃。

## 四

阮钴在东九车间部署了Balking模式——告警不再重复发送。

但阮钴继续分析——Balking模式的适用场景有限。Balking适用于——操作只需要执行一次——或者操作在特定状态下不需要执行多次。不适用于——操作需要每个线程都执行——或者操作的结果依赖线程数量。

"Balking的本质——guard标记——条件满足时——只有一个线程执行——其他线程放弃。"阮钴在规范面板上写。"guard标记必须保证可见性和原子性——volatile保证可见性——synchronized或AtomicBoolean保证原子性。"

阮钴举例——Balking适用于——初始化操作——只执行一次——多个线程同时初始化——只有一个线程执行初始化——其他线程放弃。告警发送——同一个异常只告警一次——多个线程同时检测到异常——只有一个线程发送告警——其他线程放弃。关闭操作——资源已经关闭——再次关闭时放弃——避免重复关闭。

不适用于——计数操作——每个线程的计数都需要执行——不能放弃。累加操作——每个线程的累加都需要执行——不能放弃。日志记录——每个线程的日志都需要记录——不能放弃。

阮钴在东九车间的告警系统上标记了Balking模式的使用——告警发送——AtomicBoolean guard——compareAndSet保证原子性——告警恢复——重置guard为false。

## 五

阮钴完成东九车间的Balking模式后——又在其他车间搜索了类似的问题模式——发现三个车间有类似的重复执行问题——告警重复——初始化重复——资源关闭重复。

阮钴逐一实现了Balking模式——告警重复用AtomicBoolean——初始化重复用synchronized加double-check——资源关闭重复用volatile boolean加synchronized。

"double-check——双重检查锁定。"阮钴在初始化场景中解释。"第一次检查——不持有锁——快速判断是否已初始化。如果未初始化——获取锁——第二次检查——在持有锁的情况下再次判断——防止其他线程在第一次检查和获取锁之间完成了初始化。"

阮钴写出double-check的标准模式——if (!initialized) { synchronized(lock) { if (!initialized) { init(); initialized = true; } } }。两个检查——第一个快速判断——第二个精确判断——中间加锁——保证只有一个线程执行初始化。

"double-check的关键——initialized必须是volatile。"阮钴说。"否则——第一个线程初始化完成——设置initialized为true——但其他线程可能看到initialized为false——因为initialized的写入可能被重排序。volatile保证initialized的写入对其他线程可见。"

阮钴在三个车间完成了Balking模式的部署——告警不再重复——初始化不再执行多次——资源关闭不再报错。

"放弃的艺术——知道什么时候该放弃——不是每个线程都要执行每个操作。"

阮钴走出东九车间——告警面板上的告警记录——每条异常只有一条告警——不再重复——不再遗漏——不多不少——每个异常一条。
