# 第26章：安全的错觉

## 一

铁嫂在东七车间的ConcurrentHashMap使用中发现了一个问题——复合操作非原子。

东七车间的场景——一个计数器映射表——存储每个设备的计数。每个设备对应一个计数值。多个线程并发更新计数器——检查设备是否存在——不存在则创建——存在则累加。

代码逻辑——

if (!map.containsKey(deviceId)) {
    map.put(deviceId, 1);
} else {
    map.put(deviceId, map.get(deviceId) + 1);
}

问题在于——containsKey()、get()、put()都是原子操作——但三个操作的组合不是原子的。两个线程同时执行——线程A执行containsKey()返回false——线程B执行containsKey()返回false——线程A执行put()——线程B执行put()——线程B的put()覆盖了线程A的put()——计数少了一次。

"复合操作——多个原子操作的组合——不是原子的。"铁嫂说。"ConcurrentHashMap保证单个操作的原子性——不保证复合操作的原子性。"

## 二

铁嫂调出ConcurrentHashMap的文档——containsKey()、get()、put()、remove()等单个操作是线程安全的——多个线程并发调用这些操作——不会导致数据不一致。但复合操作——如先检查再执行(check-then-act)——不是原子的——需要额外的同步。

"ConcurrentHashMap的原子操作——单个方法调用。"铁嫂在面板上写。"复合操作——多个方法调用的组合——需要额外的同步机制。"

铁嫂列举了常见的复合操作——

检查再执行——if (!map.containsKey(k)) { map.put(k, v); }——两个线程同时检查——都返回false——都执行put——后者覆盖前者。

先读再写——map.put(k, map.get(k) + 1);——两个线程同时读取——读到相同的值——都写入相同的新值——更新丢失。

条件删除——if (map.get(k) == oldValue) { map.remove(k); }——两个线程同时检查——都通过——都执行remove——可能删除其他线程更新的值。

"复合操作的原子性——需要额外的机制保证。"

## 三

铁嫂提供了几种解决方案——

方案一——使用ConcurrentHashMap的原子方法——putIfAbsent()、computeIfAbsent()、computeIfPresent()、compute()、merge()。

putIfAbsent(key, value)——如果key不存在——放入value——返回null。如果key存在——不放入——返回已存在的value。原子操作——不需要额外同步。

computeIfAbsent(key, function)——如果key不存在——使用function计算value——放入map——返回计算后的value。如果key存在——不计算——返回已存在的value。原子操作——function在key不存在时才执行。

compute(key, function)——使用function计算新value——无论key是否存在——放入map——返回计算后的value。原子操作——function在锁保护下执行——线程安全。

merge(key, value, function)——如果key不存在——放入value。如果key存在——使用function合并旧value和新value——放入map——返回合并后的value。原子操作——合并函数在锁保护下执行。

"ConcurrentHashMap的原子方法——保证复合操作的原子性。"铁嫂说。"putIfAbsent()——检查再执行的原子版本。compute()——读取再计算的原子版本。merge()——合并的原子版本。"

铁嫂用merge()改造了东七车间的代码——

map.merge(deviceId, 1, (oldValue, newValue) -> oldValue + newValue);

一行代码——如果deviceId不存在——放入1。如果deviceId存在——执行oldValue + newValue——放入新值。原子操作——线程安全——不需要额外同步。

## 四

铁嫂进一步分析了ConcurrentHashMap的复合操作边界——

"ConcurrentHashMap的原子方法——保证单个key的操作原子性。"铁嫂说。"多个key的操作——不保证原子性。"

铁嫂举例——两个key的复合更新——map.put(k1, v1); map.put(k2, v2);——两个put()都是原子的——但两个put()的组合不是原子的——其他线程可能看到k1更新但k2未更新的中间状态。

"多key复合操作——需要额外的同步机制。"铁嫂说。"可以使用synchronized块——锁住整个map——但性能差。可以使用ConcurrentHashMap的compute()嵌套——但有死锁风险。可以使用分布式锁——跨JVM的同步——但复杂度高。"

"边界——单key原子操作——ConcurrentHashMap保证。多key复合操作——需要额外同步——ConcurrentHashMap不保证。"

铁嫂在规范面板上写下ConcurrentHashMap的使用边界——

"单key原子操作——使用ConcurrentHashMap的原子方法——putIfAbsent()、compute()、merge()等。单key复合操作——不要用containsKey()、get()、put()组合——用原子方法替代。多key复合操作——需要额外同步机制——ConcurrentHashMap不保证跨key原子性。"

## 五

铁嫂完成了东七车间的ConcurrentHashMap复合操作问题修复——使用merge()替代containsKey()、get()、put()组合——计数器更新正确——不再丢失。

她在工作日志上写下ConcurrentHashMap的使用心得：

"ConcurrentHashMap——线程安全的Map——单个操作原子——复合操作非原子。常见的复合操作——检查再执行、先读再写、条件删除——需要使用原子方法或额外同步。"

"原子方法——putIfAbsent()、computeIfAbsent()、computeIfPresent()、compute()、merge()——保证单key复合操作的原子性。优先使用原子方法——不要手动组合多个操作。"

"多key复合操作——ConcurrentHashMap不保证原子性——需要额外同步机制。同步粒度——锁住整个map性能差——分区锁粒度更细——分布式锁适用于跨JVM场景。"

"一致性的边界——单key原子性——ConcurrentHashMap保证。跨key原子性——需要额外机制。理解边界——才能正确使用ConcurrentHashMap。"

铁嫂走出东七车间——ConcurrentHashMap的计数器在merge()的原子操作下正确更新——多线程并发更新不再丢失——中间状态不再暴露给其他线程。ConcurrentHashMap是线程安全的——但线程安全有边界——单个操作安全——复合操作需要谨慎。理解边界——才能正确使用。
